# SSH lab

M1.6 performed one real local integration run using a disposable Alpine/OpenSSH Docker container. See `docs/03-stages/M1_6_SSH_INTEGRATION_LAB.md` for the scenario matrix, public fingerprint, adapter fix and verified cleanup. No production server or credential was used. The lab used a dedicated Docker bridge and host port bound only to `127.0.0.1`; the container, image, network and temporary keys/password were removed afterward.

`tool/ssh_lab.dart` remains a manual harness. Required environment variables: `AGENTDECK_TEST_SSH_HOST` (loopback only), `AGENTDECK_TEST_SSH_USER`, and exactly one of `AGENTDECK_TEST_SSH_PASSWORD` or `AGENTDECK_TEST_SSH_KEY_PATH`. Optional: `AGENTDECK_TEST_SSH_PORT` (default 22), `AGENTDECK_TEST_SSH_PASSPHRASE`, `AGENTDECK_TEST_SSH_FINGERPRINT` and `AGENTDECK_TEST_SSH_ALGORITHM` (default ssh-ed25519). The key path must be outside the repository. Without a pinned fingerprint, the harness shows host/algorithm/fingerprint and accepts exact `yes` only after independent verification. With a pinned fingerprint, mismatch blocks without an approval shortcut. `AGENTDECK_TEST_SSH_RECOVER=auth` deliberately fails password authentication, then retries with the correct disposable credential in the same process; it requires a pinned fingerprint.

Run manually from the repository with `C:\Users\vszni\sdk\flutter\bin\dart.bat run tool/ssh_lab.dart` only against a new isolated local lab. Never use production infrastructure. The harness does not persist secrets or trust and does not open a terminal. Environment variables can be visible to local processes; use disposable credentials and clear variables after each run. A future revision may accept a password through a protected interactive prompt. The Docker lab should be provisioned manually with a dedicated unprivileged account, localhost-only published port and credentials outside Git. Do not mount the project or Docker socket, and remove all lab resources afterward.
